## 1. 연구 개요

### 1.1 연구 정체성

본 연구는 **단순 TCP batching 최적화가 아니다**.

TCP/QUIC 전송 계층 결정에 **콘텐츠 중요도**를 ML/RL 기반으로 통합하는 **cross-layer 적응 전송 연구**이다.

### 1.2 연관 논문 매핑

| 논문 | 역할 | 핵심 기여 |
|------|------|----------|
| **Tüker et al. (2024)** | 콘텐츠 중요도 축 | 프레임별 품질 영향 분석 |
| **Grazia et al. (2021)** | 전송 계층 메커니즘 | TCP Pacing, TSQ latency 분석 |
| **Borisov et al. (2025)** | 적응 배칭 필요성 | E2E 성능 추정 기반 결정 |

### 1.3 연구 목표

1. **Stage A**: 프레임 중요도 점수화 (0.0~1.0)
2. **Stage B**: 중요도 기반 전송 행동 선택 (5가지 FrameAction)
3. **Cross-layer 통합**: 콘텐츠 레이어 + 전송 레이어 동시 최적화

## 2. 핵심 개념: VMAF/SSIM 기반 품질 측정

### 2.1 VMAF란?

**VMAF (Video Multimethod Assessment Fusion)**은 Netflix가 개발한 지각 품질 측정 알고리즘이다.

- **목적**: 사람이 느끼는 비디오 품질을 객관적으로 수치화
- **점수 범위**: 0~100 (100 = 원본과 동일한 품질)
- **특징**: 해상도, 비트레이트, 코덱 등 다양한 요소를 머신러닝으로 통합

```
VMAF Score 해석:
  90-100: 매우 좋음 (원본과 거의 동일)
  75-90:  좋음 (대부분의 시청자가 만족)
  50-75:  보통 (품질 저하 인지 가능)
  0-50:   나쁨 (명백한 품질 저하)
```

### 2.2 SSIM이란?

**SSIM (Structural Similarity Index)**은 이미지/비디오의 구조적 유사도를 측정한다.

- **점수 범위**: 0~1 (1 = 완전 동일)
- **측정 요소**: 밝기(luminance), 대비(contrast), 구조(structure)
- **장점**: 계산이 빠르고 간단

### 2.3 본 연구에서의 활용

#### 문제 정의

> "특정 프레임을 drop(전송 포기)하면 비디오 품질이 얼마나 나빠지는가?"

#### 측정 방법

```
1. 원본 비디오 준비 (reference)
2. 프레임 N을 drop한 비디오 생성:
   - 프레임 N을 이전 프레임 N-1로 대체 ("freeze frame")
3. FFmpeg libvmaf로 품질 비교:
   - ffmpeg -i reference.mp4 -i dropped.mp4 -lavfi libvmaf ...
4. ΔQoE (품질 저하량) 계산:
   - delta_qoe = 100 - VMAF_score
   - delta_qoe_norm = delta_qoe / 100  (0~1 정규화)
```

#### 예시

| 프레임 유형 | Drop 후 VMAF | delta_qoe_norm | 의미 |
|------------|--------------|----------------|------|
| I-프레임 | 60 | 0.40 | **높은 중요도** - drop하면 품질 크게 저하 |
| P-프레임 | 85 | 0.15 | 중간 중요도 |
| B-프레임 | 95 | 0.05 | **낮은 중요도** - drop해도 품질 영향 적음 |

#### 기존 방식 vs VMAF 기반 방식

| 항목 | Heuristic (기존) | VMAF 기반 (본 연구) |
|------|-----------------|-------------------|
| 중요도 판단 | 규칙 기반 (I > P > B) | **실측 품질 영향** |
| 근거 | 코덱 구조 가정 | **객관적 측정값** |
| 정확도 | 대략적 | **프레임별 정밀** |
| 장면 적응 | 불가능 | **장면별 차이 반영** |

## 3. 시스템 아키텍처

### 3.1 2-Stage 아키텍처

```
┌─────────────────────────────────────────────────────────────────┐
│                        프레임 도착                               │
│                            │                                    │
│                            ▼                                    │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ Stage A: 중요도 점수화 (ImportanceScorer)               │   │
│  │                                                         │   │
│  │  입력: 13차원 특성 벡터                                  │   │
│  │  - IPB one-hot (3)                                     │   │
│  │  - key_frame (1)                                       │   │
│  │  - payload_bytes (1)                                   │   │
│  │  - deadline_slack (2)                                  │   │
│  │  - network_state (6): RTT, BW, loss, buffer, queue,    │   │
│  │                       estimated_batch_gain             │   │
│  │                                                         │   │
│  │  출력: importance_score ∈ [0.0, 1.0]                   │   │
│  └─────────────────────────────────────────────────────────┘   │
│                            │                                    │
│                            ▼                                    │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ Stage B: 전송 행동 선택 (select_action)                  │   │
│  │                                                         │   │
│  │  입력:                                                  │   │
│  │  - importance_score                                    │   │
│  │  - deadline_slack_ms                                   │   │
│  │  - network_state                                       │   │
│  │  - available_paths                                     │   │
│  │  - estimated_batch_gain (Borisov 2025)                │   │
│  │                                                         │   │
│  │  출력: FrameAction                                     │   │
│  │  - RELIABLE_SINGLE: QUIC Stream, 단일 경로             │   │
│  │  - RELIABLE_MULTI:  QUIC Stream, 멀티패스              │   │
│  │  - UNRELIABLE:      QUIC DATAGRAM                      │   │
│  │  - DUPLICATE:       고중요 프레임 중복 전송              │   │
│  │  - DROP:            deadline 초과 예상 → 전송 포기      │   │
│  └─────────────────────────────────────────────────────────┘   │
│                            │                                    │
│                            ▼                                    │
│                      전송 실행                                   │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 3-Layer 실험 계층

```
┌─────────────────────────────────────────────────────────────────┐
│ Layer 3: 실환경 (Real-World)                                    │
│ - Wi-Fi / LTE / 5G 실제 네트워크                                │
│ - scripts/realworld_harness.py                                 │
│ - 실측: RTT, 패킷 손실, 버퍼 이벤트                             │
├─────────────────────────────────────────────────────────────────┤
│ Layer 2: 에뮬레이션 (Emulation)                                 │
│ - Mininet 기반 네트워크 조건 시뮬레이션                          │
│ - scripts/emulation_*.py                                       │
│ - Linux 전용, 합성 네트워크 환경                                │
├─────────────────────────────────────────────────────────────────┤
│ Layer 1: 시뮬레이션 (Simulation) ← 현재 주력                    │
│ - 순수 Python 기반 전송 시뮬레이터                              │
│ - core/simulator.py, tcp_batching_core.py                     │
│ - 플랫폼 독립적, 빠른 반복 실험                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 6. 실험 환경 및 제약사항

### 6.1 Windows 환경 (현재)

**바로 사용 가능:**
- 시뮬레이션 실험: `py -3 -m jupyter lab`
- 모델 학습: `py -3 scripts/train_importance_model.py ...`
- 실환경 측정: `py -3 scripts/realworld_harness.py ...`

**Mock 모드로 동작:**
- Mininet 에뮬레이션 → MockRunner 사용 (합성 데이터)
- QUIC 스택 → MockQuicServer/Client 사용 (합성 데이터)

**사용 불가:**
- 실제 Mininet 네트워크 에뮬레이션 (Linux 전용)

### 6.2 Linux 환경

**추가 가능:**
- Mininet 에뮬레이션: `sudo apt install mininet`
- QUIC 실제 전송: `pip install aioquic`
- VMAF 라벨 생성: `sudo apt install ffmpeg libvmaf-dev`

### 6.3 권장 실험 순서

